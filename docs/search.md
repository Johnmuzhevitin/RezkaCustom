# Advanced search — 0.12.1

## Configurable candidate limit

The settings panel exposes **«Вид → Лимит проверки карточек»** with 1,000, 5,000, **10,000 by default**, 25,000 and 50,000 candidates per run. The budget counts checked titles, including nonmatches and unknown metadata, rather than displayed results. A larger budget can take longer; Stop and continuation remain available.

Each new search or continuation reads the saved preference once. Changing it during a run does not move that run's boundary. The paused message and navigation snapshot retain the actual batch limit; old snapshots retain their former 1,000-card pause, then use the new preference when continued. Invalid stored values fall back to 10,000. The setting is shared across mirrors and included in local settings backups; it is not a filter or part of a saved filter set.

## Scope and integration

The [0.8.8 validation and ordering follow-up](search-hardening-2026-11-03.md) records that earlier build's verification.

The dedicated HDrezka search page supports title, content type, genre, year range and country, with optional personal-list, actor, voice, translation-kind and rating conditions. IMDb, Kinopoisk and HDrezka scores and vote counts are independent fields. Quality and episode-level translation completeness are outside this release. The navigation entry is `Расширенный поиск`. The page uses `/search/?do=search&subaction=search&q=...#rc-search=1` with extension filters in the URL fragment. Only native search parameters reach the server. Live testing showed that including the extension's `type`/`genre`/country parameters in the server query redirects saved links to the homepage even with the native `do` and `subaction` present. The fragment avoids those conflicts and preserves normal Back navigation.

## Conditions and saved sets

- Both complex-editor entry points validate common fields before opening. Invalid year bounds, inverted ranges and country names focus the offending field without opening a modal, changing results or discarding pending input. Search submission uses the same validator before normalizing values.
- An unapplied title explains that HDrezka ordering belongs to the next title search and that the visible results belong to the previous search. Applying or reverting the title restores the ordinary title-search explanation; clearing it hides that explanation and restores the catalogue order control.
- Applied-filter chips update results without replacing unrelated form drafts. The corresponding form field or extra rule is removed only if it still matches the applied value and has no uncommitted input. Edited values, incomplete numeric rules and typed voice names remain available for explicit application. Removing the applied complex expression follows the same separation.
- Reset clears scalar, additional and complex filters while preserving the currently entered title. It starts the title search again without those restrictions; an empty title returns to the catalogue. Catalogue ordering returns to its default, and focus returns to the title field.
- Catalogue sort changes apply immediately only when the rest of the form matches the active search. With other pending edits, sorting joins the draft and waits for `Применить фильтры`; it does not submit those edits implicitly. A local `Применится вместе с фильтрами.` message beneath the sort control identifies the pending order and is linked to the visible combobox. It disappears on application, reset, reversion to the applied order or entry of a title, where native ordering takes precedence.
- Common-filter recaps use plain type, genre, country and year labels separated by middle dots. Additional rules keep their operator descriptions; saved nested expressions retain full all/any/exclusion logic. The title query remains excluded from saved sets.
- Nested condition groups have distinct accessible names (`Основная группа`, `Группа 1`, `Группа 1.1`) and contextual control names, updated when groups are removed or automatically expanded for validation. Visual labels and columns remain unchanged. Group semantics follow the [WAI guidance for related controls](https://www.w3.org/WAI/tutorials/forms/grouping/).

- Existing scalar filters and optional conditions added through `Добавить фильтр` are mandatory for every result. Multiple values in a basic voice condition default to any-of; the operator can be changed to all-of or none-of.
- `Сложные условия` opens a wide modal editor with nested all/any groups and group negation. The context shows the current title query or `По всему каталогу`, followed by the common-filter summary. It uses the form's current draft, matching what application will search, and exposes this scope as the dialog's accessible description. Collapsing a group keeps its expression; cancelling discards the modal draft. Applying validates the full query before replacing results. Empty nested groups and incomplete rules are errors; an empty root clears the advanced condition.
- `search-rules.js` owns the field registry, validation, three-valued evaluation and descriptions. `search-core.js` owns parsing, route selection, fetching and tab caches. `search-editor.js` owns the controls; `search-store.js` owns independent preset records.
- State version 2 retains the legacy scalar fields and adds `extra` rule nodes and an optional `advanced` group. Rule nodes contain `kind: rule`, `field`, `op`, and numeric `value`/`to` or list `values`. Groups contain `kind: group`, `mode: all|any`, `not`, and `children`. Validation bounds each tree to 200 nodes and 12 levels, values to 100 strings of at most 120 characters. Serialized criteria are limited to 64 KiB. No expression is executed as code.
- Numeric comparisons include inclusive ranges. List operators use complete metadata for negative proofs: a different primary genre/country does not establish absence. Missing numeric values remain unknown under numeric comparisons and negation; explicit exists/missing rules distinguish a fetched absence from data not yet fetched. An OR group may succeed on a known matching branch without requesting the unknown branch.
- All three ratings and votes are read from title HTML. Voices use the full visible name/title, retaining language and cut variants even when numeric translator IDs coincide. A metadata-row fallback handles titles without a translation picker. Translation kinds are recognized only from explicit labels; an unclassified studio does not prove the absence of a translation kind. Series matching means that the voice appears on the title, without promises about any particular episode.
- Detail metadata is cached for 30 minutes in the current tab/mirror, bounded to 1000 records. Visited title pages can populate this cache and voice suggestions without additional requests. Voice suggestions are collected names, not a claim to be a complete catalogue; exact free text is accepted. Malformed required ratings are retriable and are not cached as absent.
- A readable title can omit country or genre. These fields carry separate completeness flags, including through the tab cache. Missing/empty fields cannot establish a negative match; other known rules can still decide the candidate. Responses with neither metadata row remain retriable parsing errors.
- Source planning uses only common scalar conditions. Advanced alternatives never narrow the source route. Catalogue pages remain sequential; title-metadata concurrency starts at four and can double up to 32 when measured uncached throughput improves. Saturation or slowdown reduces it; server pressure triggers cooldown and serial recovery before cautious ramp-up. Reads remain cancellable. Results commit in catalogue order; failures abort outstanding reads and retain uncommitted candidates for retry. A batch checks the configured number of new candidates (10,000 by default) regardless of its match count or productive page count, unless the catalogue ends, loading fails, the user stops it, or 50 consecutive pages contain no new candidates. Results report titles with insufficient metadata separately; those titles count towards the budget and do not interrupt loading. Queried ratings and matching voices are explained when fetched.
- Presets use separate `chrome.storage.local` keys under `rc-search:preset:v2:`. A preset includes filters and ordering, not `q`; choosing one fills the form without running it. Create, update, rename and delete await storage completion. Corrupt presets are reported rather than applied with dropped criteria.
- Validation messages sit beside the relevant condition and focus its value, invalid range boundary or empty group's add action. The control references its message with `aria-describedby` and `aria-invalid`; valid edits or removal clear that message without dismissing independent loading errors. Invalid collapsed groups open for correction.
- Compact voice inputs use the full filter width, with the add action below. A small disclosure explains the source and limits of suggestions and series availability. Field choices are grouped into personal lists, title metadata, translation, and ratings/votes.
- The save dialog explicitly describes filters-only storage and previews the conditions and saved catalogue ordering. Title search displays `Порядок HDrezka` while preserving the user's catalogue sort choice for later use.
- Legacy links remain valid. Structured links add `v=2&rules=<JSON>` only to the fragment. Malformed or unsupported criteria stop the search with an error. Result snapshots use `rc-search:v2:`; old snapshots are not reused. Back/Forward and result/scroll restoration retain their original behavior.

## Data behavior

- Title searches use `/search/?do=search&subaction=search&q=...` and native ordering.
- Otherwise a country route takes precedence, followed by type + genre, exact release year, type, or the full catalogue. Native `filter` and numeric type IDs are retained across pagination.
- Year bounds match the title's initial release year, including series. They are inclusive. The form rejects inverted ranges; malformed bookmarked ranges are normalized.
- Primary metadata can prove a positive country/genre match. A differing primary value cannot disprove it: full detail metadata is requested for secondary countries/genres. Native country/genre sources already establish their respective condition.
- Known country names are canonicalized without regard to case. The country list offers suggestions; another site country name can be entered directly.
- Country suggestions use a themed editable combobox instead of Chrome's unstyled datalist. The popup matches the input width and opens above when space below is limited. Typing filters names; arrows and Enter choose a suggestion without submitting the form, Escape/Tab dismiss it, and `Любая страна` clears the country. Unlisted text remains editable. Keyboard behavior follows the [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/).
- Type, genre, sorting and country share one picker implementation and the same control, arrow, popup and option styles. Genre supports text filtering, while type/sorting offer fixed choices with arrow keys, Home/End and letter navigation. Only one popup opens at a time. Hidden native selects retain the validated form values; uncommitted genre text is discarded on dismissal. Changing type refreshes available genres; sorting remains disabled during title search and observes the draft rules above.
- Results are deduplicated by title ID and retained in native order. No global rating or local-per-page sort is presented as a catalogue-wide sort.
- A batch pauses at the configured candidate limit (10,000 by default). Match count and productive page count do not cause an earlier pause. A guard pauses after 50 consecutive pages without unseen candidates, and resets on any page with new candidates. The status explains a budget or stalled-pagination pause; snapshots retain that reason and the batch limit. Search never reports completion until both pending candidates and the native next page are exhausted; continuation retains unprocessed candidates from the last page and reads the currently saved limit for its next batch.
- Search controls appear beside the upper status and after the cards. Both share busy, retry, stop and completion state; they remain focusable with `aria-disabled` while busy, and repeated activation cannot create duplicate requests. Upper controls keep focus near the status: stop returns to upper continuation and completion moves to the status. Lower continuation retains its first-new-card focus behavior. Focus moved elsewhere by the user is respected. Synchronously completed buffered batches follow the same rules.
- Requests are sequential, carry the site's session and time out after 20 seconds. They follow canonical title redirects within the current mirror; Fetch `mode: 'same-origin'` rejects cross-origin hops before contacting their destination. Rejecting every redirect previously stopped rating searches at titles redirected to a `-latest.html` URL and reported a misleading connection error. See the [Fetch Standard](https://fetch.spec.whatwg.org/#concept-main-fetch). Abort and generation checks prevent a superseded query from changing the current results. Failed candidates remain pending for retry.
- HTML is parsed into inert documents. Only selected text/URL fields enter the interface; remote markup and scripts are never inserted. Card routes and pagination origins/paths are validated.
- A short-lived sessionStorage cache restores results and scroll after title navigation. Storage failure does not prevent searching. Cached item URLs and next-page paths are validated before use. This cache belongs to the current tab and mirror; it is not an account service or a cross-device history.
